
# 手書き領収書のテキストデータ抽出・分析

> 手書き領収書の画像をアップロードし、認識されたデータの確認・修正・保存ができるWebサービス

## プロジェクト概要

手書き領収書の画像をアップロードすると、OCRによって抽出されたデータを
ユーザーが確認・修正できるWebサービスを開発しました。

認識された領収書データは画面上で修正・保存できるほか、
取引先名や商品名などを条件にデータを検索し、
Excelファイルとしてダウンロードできるように実装しました。

### プロジェクトの目的

- 手書き領収書データのデジタル化
- OCR認識結果の確認・修正機能の提供
- 領収書データの検索・閲覧における利便性の向上
- 認識データをExcelファイルとしてダウンロードできる機能の提供

## 主な実装内容

### 1. グローバル状態管理（Recoil）

OCR認識結果やログイントークンなど、複数の画面で共通して使用するデータを管理するために、RecoilのAtomを活用しました。

`receiveData`と`userToken`の2つのAtomを使用して状態をグローバルに管理し、
`userToken`の初期値を`localStorage.getItem('token')`に設定することで、
ページを再読み込みした後もログイン状態が維持されるように実装しました。

### 2. ログイン・新規会員登録

ログイン成功時にレスポンスヘッダーからAuthorizationトークンを取得し、
`localStorage`とRecoilのAtomの両方に保存しました。

その後のリクエストでは、このトークンを利用して認証状態を維持するように実装しました。

新規会員登録時には、メールアドレスの重複確認APIを別途呼び出し、
パスワードと確認用パスワードが一致しているかをクライアント側で事前に検証するように実装しました。

### 3. 領収書のアップロード

ユーザーが簡単に領収書画像をアップロードできるように、
`react-dropzone`を活用したドラッグ＆ドロップ方式と、
従来のファイル選択方式（`input[type=file]`）の両方に対応しました。

`FileReader`を使用してアップロードした画像のプレビューを生成・表示し、
`FormData`を利用して画像をサーバーに送信するように実装しました。

また、OCR処理のレスポンスを待っている間は、ローディング画面に切り替わるようにしました。

### 4. OCR認識結果の確認・修正

認識された領収書データをユーザーが直接確認・修正できるように、
品目・単価・数量・金額をテーブル形式で表示しました。

単価や数量を変更すると、該当行の金額と全体の合計金額がリアルタイムで再計算されるように実装しました。

また、選択した行を基準に品目を追加・削除できる機能も実装しました。

### 5. 領収書一覧の取得・検索

ログインユーザーの領収書一覧をサーバーから取得し、
取引先名・商品名による検索と、取引期間（開始日～終了日）による絞り込みを
同時に適用できるように実装しました。

一覧のデータ件数が増えた場合にも対応できるように、
`react-js-pagination`を利用してページネーションを実装しました（1ページあたり10件）。

### 6. 領収書の詳細表示・修正・削除・Excelダウンロード

URLパラメータ（`receiptId`）を利用して、特定の領収書の詳細データを取得するように実装しました。

単価や数量を修正すると、金額と合計金額が自動的に再計算されるようにしました。

修正した内容はPUTリクエストで保存し、必要に応じてDELETEリクエストで削除できるように実装しました。

また、`xlsx`ライブラリを活用して、領収書データをExcelファイルとしてダウンロードできる機能も実装しました。

## プロジェクトの課題

### 課題の詳細

1. **領収書の処理方法**：卸売取引では、手書きと印刷された領収書が混在している。
2. **領収書の紛失問題**：領収書を紛失すると取引履歴を確認できず、業務上の問題が発生する。
3. **データ化の制約**：取引履歴を一元的に管理・分析することが難しい。

### データセットの状況

1. **ナインオンスおよび釜山C&Sから提供された領収書63枚**
   - 取引先情報（日付、連絡先、口座番号など）
   - 品目、単価、数量、金額、合計金額
2. **編集済み画像1,548枚**：領収書内の単語を個別に分割した画像
3. **AIHubデータ**
   - 手書き文字344,412件
   - 手書き単語756,813件
